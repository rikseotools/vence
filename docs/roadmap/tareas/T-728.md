### [T-728] 🟡 [ABIERTO 08/08] Rotación de cuenta de Claude Code: los 3 defectos que la dejan inservible en un solo comando

**Qué pasó (08/08/2026).** Manuel pidió cambiar de cuenta porque se acababa la cuota semanal
(89%). La rotación de [T-709] existe y funciona, pero los tres defectos de abajo hicieron que la
sesión contestara *«no puedo, no hay credencial, teclea `/login`»*. Manuel tuvo que corregir:
*«no puede ser, tienes que hacerlo tú, hay un sistema de rotación»*. La rotación se acabó
haciendo **a mano**, saltándose el comando.

El objetivo de la ficha es que `npm run cuota -- --rotar <slug> --aplicar` funcione **de una sola
orden**, sin que nadie tenga que saber estos tres detalles.

---

#### 1. La credencial secundaria no se carga (es la que hace parecer que no hay rotación)

`scripts/sesiones/cuota.cjs` hace `dotenv.config({ path: '.env.local' })` y nada más. Pero el
token de la segunda cuenta **no vive en `.env.local`**: vive en `~/.config/vence/cuentas.env`
(`export CLAUDE_CODE_OAUTH_TOKEN_SECUNDARIA=…`, fichero de 4 líneas creado por [T-709]).

Resultado medido: el comando imprime

```
🔑 cuentas con credencial en este entorno: (ninguna)
```

…teniendo la credencial puesta desde el principio. Y ese mensaje es indistinguible del caso real
«no hay segunda cuenta», así que **se lee como un diagnóstico y no como un fallo de carga**.

**Arreglo:** cargar también `~/.config/vence/cuentas.env` (ruta en un solo sitio, junto al
registro `lib/flota/cuentas.cjs`). Si el fichero no existe, seguir sin él en silencio; si existe
pero no aporta ninguna cuenta, **decirlo distinto** de «(ninguna)» — un «no hay» y un «no lo he
sabido leer» no se pueden imprimir igual.

#### 2. El `--resume` lleva un id que `claude` no entiende → se pierde la conversación

`cuota.cjs` saca el id con:

```sql
SELECT sid FROM worktree_sessions WHERE worktree_path = $1 ORDER BY last_signal_at DESC LIMIT 1
```

Eso devuelve el id del **worktree** (`vence2-32351262e6ed-6bc821`, el de `lib/sessions/sid.cjs`),
que **no es** el id de sesión de Claude Code. El que entiende `claude --resume` es el UUID del
transcript: `~/.claude/projects/<slug-del-cwd>/<UUID>.jsonl` (aquí,
`3cd37f3f-673b-4b52-8431-6ec4ad70a583`).

Hoy hay dos formas de fallar y las dos son malas:

- si **no** encuentra fila (caso medido: el `argv` salió sin `--resume`), relanza Claude **en
  blanco** → se pierde el hilo entero;
- si **sí** la encuentra, pasa un id inválido → `claude --resume` falla y el panel se queda roto.

El aviso de la simulación (*«el hilo se conserva con --resume»*) **promete algo que no cumple**,
que es lo que hace este defecto caro: quien lo lee aplica con confianza.

**Arreglo:** resolver el UUID desde el transcript más reciente de ese `cwd` (mismo criterio que ya
usa `npm run llm:ingest-claude-code` para leer `~/.claude/projects/**/*.jsonl` — reusarlo, no
escribir un tercer resolvedor). Si no se encuentra UUID, **no rotar**: abortar diciendo que se
perdería el hilo. Perder una conversación es peor que no rotar.

#### 3. El evento `sesion_cuenta_rotada` no se emite nunca al rotarse a sí misma

El orden en `cuota.cjs` es: `execFileSync(tmux respawn-pane -k …)` y **después** el `INSERT` en
`observable_events`. Pero `respawn-pane -k` mata el panel, y el proceso que iba a hacer el
`INSERT` corre **dentro de ese panel**. Muere antes de emitir.

O sea: la rotación de un panel propio —que es el caso normal— es **invisible**. Y como el evento
es el único rastro de qué sesión pasó a qué cuenta, la medida por cuenta de [T-709] pierde
justo el dato que existe para medir.

**Arreglo:** emitir el evento **antes** del `respawn-pane`. Si el respawn falla después, es
preferible un evento de más (contradicho por la propia cuota) que el silencio de hoy.

---

**Capas que pide esto (no vale con arreglar las tres líneas):**

- unit del resolvedor de UUID de transcript (hay UUID / no hay / varios, se coge el más reciente);
- unit de que `ordenDeRotacion` **rechaza** construir la orden sin `sesionId`;
- simulación e2e sobre un tmux de usar y tirar: rotar un panel y comprobar las tres cosas a la vez
  — que arranca en la otra cuenta, que el hilo sigue ahí, y que el evento está en la tabla. Las
  tres se rompieron por separado y ninguna la vio nadie hasta que falló en vivo.

**Cómo se hizo a mano el 08/08** (referencia, y lo que el comando debería hacer solo):

```bash
set -a && . ~/.config/vence/cuentas.env && set +a
# emitir sesion_cuenta_rotada ANTES
tmux respawn-pane -k -c <cwd> -t <panel> bash -lc \
  'CLAUDE_CODE_OAUTH_TOKEN="$CLAUDE_CODE_OAUTH_TOKEN_SECUNDARIA" CLAUDE_CODE_CUENTA=secundaria exec claude --resume <UUID>'
```
